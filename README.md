# Savage's Reply

**Savage's Reply** 是面向 AstrBot 的「真人群聊交互与表达中枢」插件：打通「何时回（免@智能接话/称呼必回/冷场打破/防插嘴）」与「怎么回（分段连发/打字节奏/TTS联动）」，让 Bot 如真人般自然灵动地融入群聊；同时保护代码块、表格、公式和超长正文——完整性优先，绝不因为拟人化丢内容。

当前版本 `v0.6.0`。要求 AstrBot `>= 4.22.0`；离线测试只需 Python 3.11+ 标准库。

---

## 一、它解决什么问题

| 问题 | 本插件的做法 |
| --- | --- |
| Bot 一次甩出一大段话，不像真人聊天 | 按语义切成短句逐条发出，间隔按「打字下一句」的时间计算 |
| 机械按标点切开，把代码块、表格、引号切坏 | 保护区扫描：``` 代码块、行内代码、`$$` 公式、`<think>`、表格行、成对符号内部绝不下刀 |
| 切出一堆碎片（「好的。」单独一条） | 短尾合并：末段太短并回上一段；段数超上限自动合并 |
| 干正事的长回复（总结、代码）被拆得七零八落 | 含代码块 / 表格 / 公式、或超过字数上限的回复**整条完整发送** |
| 聊天节奏均匀得像机器 | 延迟 = 基础 + 字数 × 每字时间 × 随机抖动，首段立即发，总延迟有上限 |
| 真人打字时对方会看到「正在输入」 | 私聊分段等待期间调用平台输入状态（NapCat / aiocqhttp 私聊有效，失败静默） |
| 正则断句不如模型懂语义 | 每轮临时注入输出规范，模型可用 `[[next]]` 自己决定断句边界；不用则回落本地引擎 |
| 开了 TTS 时一半文字一半语音 | 检测到框架 TTS 激活后由插件**逐段合成语音**并逐段发送（框架只会把整条链塞进一条消息） |
| 模型偶尔一本正经地编造 | 可选风险扫描（纯规则、零延迟）：可疑承诺、无出处统计、未提及链接只记录不阻塞 |

明确不做：记忆、人格注入、图片/语音消息、非 LLM 消息、主动消息拦截。检测到 AstrBot 内置「分段回复」开启时只警告，不自动改配置。

## 二、安装

目录名保持 `astrbot_plugin_savagereply`。放到 `AstrBot/data/plugins/` 后重载插件即可。

**建议**：如果开启了本插件，请把 AstrBot 设置 → 拓展功能里的内置「分段回复」关掉，避免双重分段（插件会日志提示）。

## 三、插件页面（输出画廊）

AstrBot WebUI → 插件 → Savage's Reply → 打开插件页面，是一本「输出画廊」：

- 背景是 StyleKit 的真实丝绸动态素材（已转制为自动循环的 WebP 动图）：打开页面即流动，无需点击；
  动图加载失败时退回静态漂移层，`prefers-reduced-motion` 下只显示静帧；
- 首屏之后是横向功能画册，滚轮、触屏滑动、鼠标拖动或键盘翻阅 5 帧，右上角计数同步；
- 五帧各自使用色板中的一种底色：Porcelain / Stone / Taupe / Gold / Ink；
- 每帧角落「翻阅详情」打开内页，可现场改写该功能的开关；
- 页面只写 14 个布尔开关（白名单校验），字数、延迟等数值参数仍去插件设置页调整；
- 风格为 Luxe Lookbook：瓷白底、墨黑字、唯一哑光金，方角与 hairline，无圆角/阴影/渐变。

## 四、工作原理（简版）

```text
模型回复生成
    ↓
[on_decorating_result 钩子]  ← 本插件在这里，全场最低优先级
    1. 规则分流：含代码块/表格/公式/超长 → 原样放行（完整性保护）
    2. 风险扫描（可选）：命中只记录，不阻塞
    3. 智能分段：保护区 → 区间断点 → 短尾合并 → 段数上限
4. 逐段发送：全部由插件发出；第一段复刻框架的引用 / @ / 回复前缀，其余段保持干净（与内置分段行为一致）
   （打字延迟开启时）每条之间等待「打字下一段」的时间，失败自动合并剩余内容兜底
   特殊：TTS 激活时插件逐段合成语音（可选 dual_output 同时补文字），仍按分段节奏发送；内置分段开启时同样全部自行发送，不会二次切割
    ↓
[框架内置] 分段 / TTS / 转图 / 合并转发（已关内置分段则不受影响）
    ↓
发送
```

分流规则（顺序即优先级）：代码块 → 表格 → `$$` 公式 → 超过 `max_total_chars` → 低于 `min_total_chars` → 其余进入分段。

### 场景预设（Presets）与指令

插件提供开箱即用的预设档位，既可在 WebUI 下拉菜单选择，也可使用群聊/私聊指令便捷管理：

| 预设档位 | 定位与特征 | 适用场景 |
| --- | --- | --- |
| `natural` (默认) | **日常拟人推荐档**：拟人分段打字、停顿与输入状态全开，关闭主动接话，防炸群打扰 | 日常对话、常规群聊与私聊 |
| `lively` | **群聊气氛组档**：在拟人分段基础上开启真人群聊智能接话（smart 模式）与 25s 冷场打破 | 活跃社群、活跃水群、Bot 陪聊 |
| `instant` | **极速直答档**：关闭所有打字延迟与断句标记，整条直发秒回不分段 | 客服接待、知识库高效查询、生产力场景 |
| `custom` | **专家自定义档**：完全由用户在 WebUI 手动微调 40+ 配置项，零预设接管 | 深度发烧友自由定制 |

**快捷指令（管理员/主人）：**
- `/sreply preset`：查看当前生效预设及可选档位
- `/sreply preset diff <档位>`：比对当前配置与目标预设的差异清单（提前查看将变更的项）
- `/sreply preset apply <档位>`：一键应用预设方案（显示变更明细）
- `/sreply preset apply custom`：一键切回专家自定义模式

## 六、防幻觉：各层分工与提示词指南

完全消除幻觉在技术上做不到（LLM 是概率预测）。正确做法是分层防御，本插件只承担**出口风险提示**这一小层：

| 层级 | 手段 | 落在哪 | 状态 |
| --- | --- | --- | --- |
| 让模型「少编」 | 人格提示词约束 | AstrBot 人格管理 | 你手动加，见下 |
| 给模型「真知识」 | RAG：记忆注入 / 知识库 | Savage Type / AstrBot 原生知识库 | 已有 |
| 让模型「能查证」 | 联网搜索工具 | web_search / 搜索类插件 | 生态已有 |
| 降低随机编造 | 温度调低（事实类任务 0~0.3） | Provider 参数 | 你手动调 |
| 出口把关 | 轻量风险扫描 | **本插件** | 可选开启 |

### 推荐加进人格提示词的约束（可直接复制）

```text
回答依据优先级：我方提供的参考资料/记忆 > 你的通用知识 > 推测。
不确定时明确说「我不太确定」，禁止编造事实、数据、链接、引用。
不虚构任何统计数字、研究出处、新闻事件；如果无法确认，就说查不到或不了解。
发现自己前面说错了，直接承认并纠正。
```

### 本插件风险扫描的边界（诚实说明）

- 纯正则规则，**零延迟零成本**，只发现明显模式：可疑承诺词、「据 xx 统计」式无出处声明、用户没提过的链接；
- 命中默认**只写日志**，不修改回复（避免引入新错误）；可切换为追加一句不确定提示；
- 它**不是**事实核查，不联网、不调用模型、不能判定内容真假。想要更强的出口核查（二次模型验证），延迟和成本都会翻倍，不适合聊天场景，本插件有意不做。

## 八、灵感与边界

- 分段保护（代码块/表格/成对符号）、双保险防重入：参考 [astrbot_plugin_splitter](https://github.com/nuomicici/astrbot_plugin_splitter) 的公开实现思路；发送模式改为全部自行发送并把框架回复头复刻到第一段（修正「只有最后一段带引用」的不一致）。
- 区间断点、弹性延伸、短尾合并：参考 [astrbot_plugin_custome_segment_reply](https://github.com/LinJohn8/astrbot_plugin_custome_segment_reply)。
- 输出管道定位（13 阶梯）：参考 [astrbot_plugin_outputpro](https://github.com/Zhalslar/astrbot_plugin_outputpro)。
- 打字节奏模型（每字耗时 × 抖动、首条立即、气泡间隔）：参考 typecaast、CipherTalk、OpenClaw 等项目的通用实践。
- 防幻觉分层（RAG / 提示词 / 约束解码 / 出口验证）：参考 Chain-of-Verification、RefChecker、GroundCheck 等公开研究与实践，本插件只吸收「出口轻量扫描」这一最小可行部分。
- AstrBot 插件开发文档：https://docs.astrbot.app/dev/star/plugin-new.html
- 插件页面的丝绸动态背景素材（`pages/lookbook/assets/silk.webm` + `silk-poster.avif`）来自开源风格库 [StyleKit](https://github.com/AnxForever/stylekit)（MIT License），风格规范亦参考其 Luxe Lookbook 条目。

**明确不做**：情绪数值、主动陪伴、改写人格文件、错字/撤回/typing、合并转发与转图兜底——留给后续版本按需评估。TTS 只做「逐段合成 + 逐段发送」：框架自身会把整条链塞进一条消息，所以分段与语音必须由插件一起完成（`dual_output` 时会同时补文字）。
